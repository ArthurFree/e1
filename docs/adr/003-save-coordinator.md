# ADR 003：SaveCoordinator 保存协调器

## 背景

旧保存实现中，防抖触发、flush 与重试可并发执行同一个 async 保存函数，存在三类数据安全缺陷：乱序完成时旧内容覆盖新内容；旧保存把仍有未保存内容的 UI 误报「已保存」；旧快照的孤儿附件清理误删新附件。此外 beforeunload 无法保证 IndexedDB 异步写入完成。

## 决策

每个文档一个 `DocumentSaveCoordinator`（application 层）：每次编辑 generation + 1；同一文档保存串行执行；队列只保留最新快照；旧代次完成不发布 saved、不执行附件清理与自动版本；失败保留快照重试。beforeunload 之外增加 localStorage 恢复缓冲（仅正文 JSON），保存成功按代次清除，启动时比对提示恢复。

## 原因

- 串行 + 代次是消除整类并发缺陷的最小机制，且可完整单测；
- 恢复缓冲把「关闭页面可能丢内容」从概率问题变为可恢复流程。

## 结果

- 竞态行为由阶段 0 基线测试（乱序保存/文档切换/附件竞态）持续回归；
- 被否决的替代方案：保存加分布式锁/事务合并（IndexedDB 单连接串行下无必要）、内容哈希判等（不能解决误报 saved 与附件误删）。
