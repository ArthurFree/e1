## 3. R11C-01：消除 `fs.rename → journal update` Crash Window

当前粗粒度流程：

```text
journal = rewriting
↓
rewrite Markdown
↓
fs.rename
↓
journal = relocated
```

存在窗口：

```text
fs.rename 已成功
↓
进程 / OS 崩溃
↓
journal 仍为 rewriting
```

恢复不能只依赖 `phase`。

### 目标

每个不可逆文件系统步骤都必须：

```text
持久化 intent
↓
执行 fs 操作
↓
持久化 applied
```

恢复时结合：

```text
journal intent
+
from / to / hop 实际存在状态
```

决定回滚，不得猜测。

### 建议 Journal v2

```ts
type FileOperationStepState =
  | "pending"
  | "intent"
  | "applied"
  | "rollback-intent"
  | "rolled-back"
  | "recovery-required";

interface JournalPathStep {
  id: string;
  kind: "document" | "group";
  fromRelativePath: string;
  toRelativePath: string;
  hopRelativePath?: string | null;
  state: FileOperationStepState;
  hopState?:
    | "none"
    | "to-hop-intent"
    | "at-hop"
    | "to-target-intent"
    | "at-target";
}

interface FileOperationJournalV2 {
  version: 2;
  operationId: string;
  vaultId: string;
  kind: FileOperationKind;
  phase:
    | "prepared"
    | "rewriting"
    | "relocating"
    | "committed"
    | "rolling-back"
    | "recovery-required";
  backups: JournalBackup[];
  pathSteps: JournalPathStep[];
  createdAt: string;
}
```

普通 rename 的恢复规则：

```text
from exists + to missing  → rename 未发生
from missing + to exists  → rename 已发生，执行 to → from
from exists + to exists   → 无法安全判定，recovery-required
from missing + to missing → 无法安全判定，recovery-required
```

## 5. R11C-03：不兼容 / 损坏 Journal 不得静默忽略

建议读取结果显式分类：

```ts
type JournalReadResult =
  | { kind: "ok"; journal: FileOperationJournal }
  | { kind: "missing" }
  | { kind: "corrupt"; reason: string }
  | { kind: "unsupported-version"; version: number };
```

`corrupt` / `unsupported-version` 必须进入：

```text
FILE_OPERATION_RECOVERY_REQUIRED
```

并阻止危险写操作。

---

## 6. R11C-04：Partial Rollback 不得删除 Journal

只要任一路径回迁失败，即使 Markdown backup 已恢复，也不得删除 journal。

必须：

```text
phase = recovery-required
```

并保留只含相对路径的诊断信息。

原则：

> 只有 confirmed committed 或 confirmed safely rolled back 才能删除 journal。

---

## 7. R11C-05：Backup 命名避免碰撞

不要只做：

```text
a/b.md → a__b.md
```

建议：

```text
backup/<sha256(relativePath)>/<basename>
```

或：

```text
backup/<step-id>.md
```

真实 `originalRelativePath` 只存在 manifest。

---

## 8. R11C-06：真正 Source-preserving 的 Markdown Patch

文件路径改写不得先做整文件：

```ts
markdown.replace(/\r\n/g, "\n")
```

否则 CRLF 文件会整体变为 LF。

必须保持：

```text
line ending
UTF-8 BOM
Frontmatter
link label
link title
fragment
whitespace
code fence
inline code
所有未命中字节
```

只允许目的地发生变化：

```diff
-[目标](旧目录/目标.md)
+[目标](新目录/目标.md)
```

测试矩阵：

```text
LF / CRLF / BOM
Chinese path / spaces
angle destination
fragment / title
image
multiple links same line
code fence / inline code
frontmatter unknown fields
```


---

## 14. 核心不变量

### REV-01：Revision 是正文历史，不是文件树 / 元数据历史

恢复默认只恢复：

```text
Document Body
```

不恢复：

```text
physical filename
relative path
workspace/group
title
tags
stable id
created
aliases
unknown Frontmatter metadata
```

### REV-02：Desktop 权威快照必须是 Raw Markdown Body

不能把以下作为 Desktop 历史的唯一真相：

```text
Tiptap JSON
textSnapshot
SQLite
```

正确关系：

```text
Raw Markdown Body Snapshot
        ↓ parse
Tiptap JSON / text preview
        ↓
UI
```

Desktop restore 不应走：

```text
历史 JSON → MarkdownCodec.serialize → 写回
```

否则可能重新格式化历史 Markdown。

### REV-03：恢复正文时保留当前 Frontmatter

恢复后：

```text
id/title/tags/created/aliases/extra 保持当前值
updated 推进到恢复时间
physical path 不变
```

### REV-04：Revision History 不是 Derived Data

```text
SearchIndex / LinkIndex → 可 rebuild
Revision snapshots       → 不可 rebuild
```

因此 Revision 不能只存在 SQLite。

---

## 15. 存储位置

建议：

```text

```

理由：


## 17. Revision Identity

### 有 Stable ID

```text
stableNoteId → 固定 revision series
```

文件 rename/move 后历史不变。

### Path-only 文档

创建随机 `seriesId`，`series.json` 保存当前路径。

E1 内部 R011 rename/move 时同步更新 series path。

外部程序移动且没有 stable id 时，R012 v1 **不猜测身份**；后续可由 R014 继续增强 adoption / portability。

## 18. Snapshot 原子创建

snapshot 是不可变用户数据。

建议：

```text
<revisionId>.tmp-<random>/
├── manifest.json
└── body.md
```

全部写完后：

```text
rename(tempDir, revisionDir)
```

中断留下的 temp dir 可在启动时清理。

## 19. Snapshot 去重

Desktop 去重依据：

```text
raw Markdown body SHA-256
```

若最新：

```text
bodySha256 == currentBodySha256
```

则 `add() → null`。

```ts
interface RevisionSummary {
  id: string;
  pageId: string;
  createdAt: number;
  reason: RevisionReason;
  bytes: number;

interface RevisionRepository {
```

## 22. Capture 与 SaveCoordinator

保留现有保存顺序：

```text
content commit
↓
revision.add
↓
revision.pruneInterval
↓
attachment cleanup
↓
recovery cleanup
```

Desktop `revision.add()` 不把传入 `contentJson` 当权威快照，而是成功保存后由 Main 重新读取当前 Markdown 并 capture raw body。

### 自动版本

```text
保存成功
+
距上个 interval >= 5 min
↓
interval snapshot
```

自动 snapshot 失败：

```text
正文仍算 saved
revision maintenance warning
```

不得污染正文保存状态。

### 手动版本

```text
用户点击“创建版本”
↓
flush pending save
↓
保存成功
↓
manual snapshot
```

如果 flush 发生 conflict / lossy / IO error，不创建与编辑器状态不一致的手动版本。

## 23. Safe Restore

Desktop 不能简单复用：

```text
revision.contentJson → controller.restore → serialize
```

建议引入平台无关协调层：

```ts
interface RevisionRestorePort {
  restore(input: {
    pageId: string;
    revisionId: string;
    expectedVersion: ContentVersionToken;
  }): Promise<{
    version: ContentVersionToken;
    updatedAt: number;
  }>;
}
```

UI 不判断 platform。

### Desktop Restore 流程

```text
点击恢复
↓
flush pending autosave
↓
读取当前 version token
↓
capture 当前正文为 before-restore
↓
revision.restore(expectedVersionToken)
↓
Main 再次校验磁盘版本
↓
读取 current Frontmatter
↓
取 historical raw body
↓
source-preserving 合并
↓
AtomicFileWriter
↓
返回新 version token
↓
更新 SourceCache
↓
重新 parse Markdown / 更新 editor
↓
LinkIndex.upsert
↓
SearchIndex.upsert
```

### 并发规则

```text
restore 前必须 flush
restore 必须 optimistic lock
外部编辑导致 token 变化 → DOCUMENT_CONFLICT
old autosave 不得覆盖 restore
```

如果 `before-restore` 已创建但 restore 随后因冲突失败，允许保留该安全快照。

## 25. Trash / Restore / Purge

```text
Trash   → revision 保留
Restore → revision 继续属于同一文档
Purge   → 正文永久删除成功后 purge revision series
```

Finder / Git / VS Code 外部删除 Markdown：

```text
不要自动删除 .e1/revisions
```

文件稍后带相同 stable id 回来时可以重新关联。

```text
+
```


### Restore Conflict

```text
DOCUMENT_CONFLICT
+
不修改 Markdown
```

### Restore IO Error

Atomic writer 保证原 Markdown 不被 truncate。

### Index Reconcile 失败

```text
正文 restore 已成功
+
derived index degraded
+
允许 rebuild
```

不能只因 derived index 失败回滚已成功的 Markdown restore。

## 44. Security Boundary

Renderer 允许传：

```text
vaultId
pageId / noteKey
relativePath
revisionId
reason
expectedVersionToken
```

不得传：

```text
absolutePath
generic fs operation
```

Revision snapshot 可能包含用户正文，因此：

```text
不记录 raw body 到日志
不记录 telemetry 正文
错误消息不拼完整 Markdown
```

允许诊断：

```text
revisionId
reason
bodyBytes
relativePath
errorCode
```

## 47. 非目标

R012 v1 不做：

```text

block-level history
```
