# Part B：R014.1 验收

## 2. Same-Filesystem Relocation Crash Safety

当前实现已经升级为：

```text
prepared
    ↓
persist rename-intent
    ↓
fs.rename(source, destination)
    ↓
persist rename-applied
    ↓
registry-updating
    ↓
registry-updated
```

避免了原来的：

```text
prepared
→ fs.rename
→ crash
→ journal 无法证明 rename 已完成
```

的问题。

Recovery 也不再只依赖 journal phase，而是结合：

```text
source exists?
destination exists?
destination vaultId?
destination fingerprint?
```

判断。

典型规则：

```text
rename-intent
source exists
destination missing
→ rename 未执行
→ 可 abort

rename-intent
source missing
destination exists + valid
→ rename 已执行
→ complete registry

source + destination 都存在
→ manual-required

source + destination 都缺失
→ manual-required
```

### 当前判断

```text
R014.1 Relocation Crash Safety
= 基本通过
```

---

## 3. Destination Snapshot

Cross-Vault transfer 的 Destination Snapshot 当前已经覆盖：

```text
notes
directories
managed assets
revision series
stable note identities
```

Plan 生成：

```text
destinationFingerprint
```

Execute 前重新计算。

只要 Preflight 后 Destination 发生变化：

```text
VAULT_TRANSFER_STALE_PLAN
```

旧 Plan 不再执行。

这修复了之前：

```text
Preflight
target assets/foo.png 不存在

↓ 外部程序创建 assets/foo.png

Execute old plan
→ 静默覆盖
```

的风险。

---

## 4. Asset No-Clobber

Managed Asset 写入已经从普通覆盖语义改为 exclusive copy。

当前语义应保持：

```text
target missing
→ exclusive copy

target exists + same sha256
→ reuse

target exists + different sha256
→ stale / collision
```

### 不变量

```text
PORT-CLOSE-03

任何 Cross-Vault 操作都不得静默覆盖目标用户已有文件。
```

---

## 5. Stable Note ID Collision

Cross-Vault Move 会保留 Stable ID：

```text
sourceStableId
=
destinationStableId
```

但现在执行前已经扫描目标 Vault。

如果目标已经存在：

```text
same stable id
```

则：

```text
VAULT_TRANSFER_IDENTITY_COLLISION
```

并阻断操作。

### 不变量

```text
PORT-CLOSE-04

Stable Note ID 在单个 Vault 内必须唯一。
```

---

## 6. Revision Series Collision

Move 迁移 Revision 时已经增加：

```text
destination revision series exists?
```

检查。

如果目标已经存在相同 series：

```text
VAULT_TRANSFER_REVISION_COLLISION
```

不进行：

```text
merge
overwrite
implicit reuse
```

Revision copy 采用：

```text
source series
    ↓
staging
    ↓
verify hash/tree
    ↓
rename to final
```

因此 Revision 的 no-clobber 语义已经明显强于上一版。

## 8. Recovery 语义

对于：


```text

```
