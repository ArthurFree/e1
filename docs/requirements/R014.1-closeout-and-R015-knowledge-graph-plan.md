## 3. R014.1 核心不变量

### PORT-CLOSE-01：任何路径切换都必须可从 Durable State 恢复

不能依赖：

```text
内存变量
当前进程状态
某个粗粒度 phase
```

判断某次物理 rename 是否已经完成。

恢复依据必须是：

```text
durable journal
+
source/destination 实际文件系统状态
```

### PORT-CLOSE-02：Destination Snapshot 必须覆盖所有会被写入的对象

Preflight 后，下列任何对象发生变化，都必须让旧 Plan stale：

```text
Documents
Directories
Managed Assets
Revision Series
Stable Note Identity
```

不能只检查目标 Markdown 路径。

### PORT-CLOSE-03：执行阶段永不静默覆盖用户已有文件

所有新建写入默认：

```text
exclusive create / no-clobber
```

只有以下情况允许 reuse：

```text
目标已存在
+
内容 hash 完全一致
+
语义明确允许复用
```

否则必须：

```text
stale / collision
```

### PORT-CLOSE-04：Stable Note ID 在一个 Vault 内必须唯一

Cross-Vault Move 保留 Stable ID，但前提是：

```text
destination Vault
不存在相同 Stable Note ID
```

若存在：

```text
VAULT_TRANSFER_IDENTITY_COLLISION
```

并阻断 Move。

### PORT-CLOSE-05：Revision Series 不允许隐式 merge / overwrite

目标 Vault 已存在：

```text
seriesIdForStableNoteId(id)
```

时，不能通过目录 copy 把两个 series 合并。

必须阻断并显示冲突原因。

### PORT-CLOSE-06：Source 在 Destination 验证完成前永不删除

沿用 R014 既有原则。

对于 EXDEV：

```text
copy
→ verify
→ destination durable
→ registry
→ source delete
```

Source delete 永远是最后阶段。

### PORT-CLOSE-07：Ambiguous Recovery 必须进入 manual-required

不能猜测：

```text
删除哪一侧
哪一侧是最新
哪个目录是用户主动创建
```

无法证明安全时：

```text
manual-required
```

比“自动修复错误”更安全。

建议将 Vault Relocation Journal 从当前的 coarse phase 状态升级。

interface VaultRelocationJournalV2 {

## 5. Stage 1：修复 Same-Filesystem Rename Crash Window

当前危险窗口：

```text
journal = prepared
↓
fs.rename(source, destination)
↓
PROCESS CRASH
↓
journal 仍是 prepared
```

R014.1 应改为：

```text
prepared
↓
persist rename-intent
↓
fs.rename(source, destination)
↓
persist rename-applied
↓
update registry
```

### Recovery 判定

不能只根据 phase。

需要检查：

```text
source exists?
destination exists?
vaultId matches?
destination fingerprint matches?
registry points where?
```

建议决策表：

| Journal | Source | Destination | 处理 |
|---|---:|---:|---|
| rename-intent | 存在 | 不存在 | rename 尚未完成，可安全回到 clean |
| rename-intent | 不存在 | 存在且 vaultId/fingerprint 正确 | rename 已完成，推进 Registry |
| rename-intent | 存在 | 存在 | `manual-required` |
| rename-intent | 不存在 | 不存在 | `manual-required` |
| rename-applied | 不存在 | 存在且验证正确 | 推进 Registry |
| rename-applied | 存在 | 存在 | `manual-required` |

禁止：

```text
phase == prepared
→ 直接删除 journal
```

## 6. Stage 2：Destination Snapshot 完整化

Cross-Vault Plan 需要生成完整 Destination Snapshot。

建议：

```ts
interface DestinationSnapshot {
  notes: Array<{
    relativePath: string
    exists: boolean
    stableNoteId?: string
    sha256?: string
  }>

  assets: Array<{
    relativePath: string
    exists: boolean
    sha256?: string
  }>

  revisions: Array<{
    seriesId: string
    exists: boolean
    fingerprint?: string
  }>

  directories: Array<{
    relativePath: string
    exists: boolean
  }>
}
```

然后生成：

```text
destinationFingerprint =
SHA256(canonical-json(snapshot))
```

Execute 时必须重新计算。

任何差异：

```text
VAULT_TRANSFER_STALE_PLAN
```

## 7. Stage 3：No-Clobber Execution

### Markdown

继续：

```text
writeFile(..., flag: "wx")
```

### Managed Asset

禁止普通覆盖式：

```ts
copyFile(from, to)
```

改成 no-clobber。

语义：

```text
target missing
→ copy

target exists + same sha256
→ reuse

target exists + different sha256
→ stale/collision
```

### Revision Series

禁止直接 merge directory。

目标 series 不存在：

```text
copy to staging
→ verify
→ atomic rename
```

目标 series 已存在：

```text
block
```

除非未来明确设计 Revision Merge，本需求不做自动合并。

## 8. Stage 4：Stable Identity Collision Gate

在 Move Plan 中建立：

```text
destinationStableIds: Set<string>
```

对于每个：

```text
sourceStableId
```

检查目标 Vault。

若目标已有相同 ID：

```text
blocker:
VAULT_TRANSFER_IDENTITY_COLLISION
```

Preflight UI 应明确显示：

```text
目标知识库已存在具有相同内部身份的文档。

源：
A/foo.md

目标：
B/bar.md

Stable ID：
01...
```

不能只显示普通路径 collision。

## 9. Stage 5：Revision Collision Gate

Move 计划中逐个检查：

```text
sourceRevisionSeriesId
destinationRevisionSeriesId
```

若 destination series 已存在：

```text
VAULT_TRANSFER_REVISION_COLLISION
```

除非它能够被证明就是目标文档自身的同一 series；当前 R014.1 建议采用保守策略：

```text
exists → block
```

未来若需要智能 merge，另立需求。

## 10. Stage 6：Cross-Vault Operation Journal

R014 当前 Cross-Vault Copy / Move 没有独立持久 Journal。

R014.1 建议至少为 **Move** 增加 Durable Transfer Journal。

因为 Move 涉及：

```text
copy docs
copy assets
copy revisions
rewrite links
trash source
rebuild destination
rebuild source
```

属于明显的多资源事务。

建议：

```text
userData/
└── vault-transfers/
    └── <operationId>.json
```

示意：

```ts
type TransferPhase =
  | "prepared"
  | "destination-writing"
  | "destination-ready"
  | "source-trashing"
  | "source-trashed"
  | "committed"
  | "recovery-required"
```

### Copy

Copy 可以允许：

```text
source 永远不动
destination partial failure → recovery/remove operation-owned staging
```

### Move

必须满足：

```text
Destination 完整且验证成功
    ↓
Source 才能进入 Trash
```

## 18. R015 核心不变量

### GRAPH-01：Graph 是 Derived Data

```text
Markdown
= Truth

LinkIndex
= Derived Link State

Graph
= Derived Projection
```

Graph 可以丢弃和重建。

### GRAPH-02：Node Identity = Stable Page ID

Node 不使用 title。

```text
nodeId = stablePageId
```

Path 只是当前展示属性。

### GRAPH-03：Never Resolve by Title

禁止：

```text
title → node identity
```

同名文档完全合法。

### GRAPH-04：Graph Failure Never Blocks Save

任何：

```text
Graph query
Graph layout
Graph rendering
```

失败都不能影响 Markdown save。

### GRAPH-05：Large Graph Query Must Be Bounded

不能：

```text
每次打开文档
→ 扫完整 Vault
→ Renderer 建整张图
```

Local Graph 必须：

```text
depth <= configured depth
nodeLimit
edgeLimit
```

### GRAPH-06：UI 不感知 SQL / Filesystem

React 只依赖：

```text
GraphQueryPort
```

不能：

```text
import sqlite
import fs
读取 vault path
```

### GRAPH-07：Rename / Move 不改变 Graph Node Identity

```text
Stable ID unchanged
→ graph node unchanged
```

只更新：

```text
title/path metadata
```

### GRAPH-08：Broken Link 是 Edge State

失效链接不是虚构 Document Node。

例如：

```text
A.md
→ missing/B.md
```

表示：

```ts
{
  sourceNodeId: A,
  targetNodeId: null,
  state: "broken",
  unresolvedHref: "./missing/B.md"
}
```

### GRAPH-09：Graph Query 只依赖可重建数据

Graph 不建立新的不可恢复用户事实。

用户事实仍保留在：

```text
Markdown
```
